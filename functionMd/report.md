# 보고서 — 기능 정의

> 화면은 모두 루트 `index.html` 한 장 안에서 해시 경로로 연다 (2026-11-07 outputs/ 에서 루트로 옮김).

## 1. 기본 원칙
- 참고자료의 보고서 유형·내용은 살리되 폰트·CSS·차트는 모두 index.html 스타일로 바꾼다 (proto 토큰, secCard·xtb·hbars·donutTable·steps·badge 조각).
- 수치·문구는 참고자료의 예시 데이터를 그대로 쓴다. 요청·장애·변경 번호는 CLAUDE.md §3 SR 번호 형식(SR+YYMMDD_5자리)으로 바꿨다(전사 예시 번호).
- 출력 단추(PDF·DOCX·HWPX)는 자리만 둔다 — 누르면 아무 일도 하지 않는다.

## 2. 구조
- 메뉴 : 보고서, 메뉴위치는 서비스관리 아래
- 하위메뉴 : 보고서 > 보고서생성, 보고서 > 보고서조회
- 메인 프레임을 좌측과 우측으로 놔누고 좌측에서 보고서 트리 표현
- 트리 : NKIA(최상위), 하위에 품질과 운영.
- 품질에 참고자료로 넣은 4개 보고서를 모두 넣어둔다.
- 보고서 에서 PDF, DOCX, HWPX 버튼을 만들어 출력한다(버튼만 만들고 실제 출력하지 않)

### 2-1. 구현 (2026-11-13)
| 메뉴 | 경로 | 화면 |
|---|---|---|
| 보고서 > 보고서생성 | `#/report/create?r=<id>` | 좌측 트리 + 우측 「보고서 생성」 조건(보고서 양식·보고기간·작성부서, 초기화·미리보기·보고서 생성) + 미리보기(출력 단추 + 보고서) |
| 보고서 > 보고서조회 | `#/report/view?r=<id>` | 좌측 트리 + 우측 보고서(머리줄 출력 단추 PDF·DOCX·HWPX). 폴더를 고르면 그 아래 보고서 목록 |

- 트리 노드 id: `nkia`(NKIA) › `qual`(품질) › `req`·`sla`·`inc`·`chg` / `ops`(운영, 비어 있음 → 「등록된 보고서가 없습니다」). 폴더 앞 화살표로 접고 편다.
- 품질 보고서 4종 (REPORTS 상수, 블록 kpi·cols·bars·donut·table·steps·note)
  1. `req` IT 서비스 요청 처리 현황 보고서 — 주요 운영 지표·유형별 접수(가로 막대)·잔여 업무 상태(도넛)·유형별 처리 상세·주요 지연 요청·분석 및 조치 계획
  2. `sla` IT 서비스 수준(SLA) 평가 보고서 — SLA 종합 지표·서비스별 SLA 성과·평가 점수·위반 원인·SLI·평가 의견
  3. `inc` 장애 발생 및 조치 분석 보고서 — 핵심 지표·등급별·원인별·주요 장애·대응 절차(단계 카드)·개선 계획
  4. `chg` 변경 및 배포관리 실적 보고서 — 핵심 지표·유형별 접수·처리 현황(도넛)·주요 변경·점검 항목·개선 계획
- 보고서 한 장 = 머리(코드·제목·설명·보고기간/대상/작성부서, 아래 굵은 선) + 블록 카드(secCard) + 꼬리(비고 · 01 / 04).
- A4 표시 (2026-11-13): 보고서 한 장은 A4 세로 고정 크기(210×297mm, 여백 16·16·13mm, `.x-rpt-a4`)로 그려 출력 모양을 미리 본다. 차트·위젯은 위아래로 늘리지 않고, 내용이 모자라면 아래를 빈 공간으로 두며 꼬리는 맨 아래(mt-auto)에 붙는다. 4종 모두 한 장 안에 들어가야 한다 — 블록 간격 gap-2, 도넛 높이 140px.
- 보고서생성: 「미리보기」는 입력한 보고기간·작성부서를 미리보기 머리에 반영, 「보고서 생성」은 생성 완료 안내(목업)와 보고서조회 바로가기. 다른 양식을 고르면 조건은 처음 값(2026-10-01 ~ 2026-10-31, 양식의 작성부서)으로 돌아간다. 보고서조회는 늘 처음 값으로 보여 준다.
- 머리줄 사용자는 관리자(박정훈) — 메뉴 role admin.
